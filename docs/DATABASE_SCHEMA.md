# Database Schema Reference

## Quick Reference

### Core Entities

| Entity | Storage | Description |
|--------|---------|-------------|
| **User** | `data/users.json` | User accounts with authentication data |
| **ResetFile** | `data/{userName}/{fileName}.json` | Pixel art documents |
| **Pixel** | Embedded in ResetFile | Individual pixel color data |
| **PaletteColor** | Embedded in ResetFile | Predefined color palette |

---

## Entity Details

### User Entity

**Purpose:** Represents a user account with login credentials and file ownership.

**Fields:**
- `userName` (string, required, unique): Login identifier
- `email` (string, required, unique): Contact email  
- `passwordHash` (string, required): bcrypt hash of password
- `files` (string[], required): List of file names owned by this user

**Example:**
```json
{
  "userName": "artist_jane",
  "email": "jane@example.com",
  "passwordHash": "$2b$10$H4qdEhY7PQJX4jjKg5CvwuMNp8x.KdU9Q4F3X8Z2Q5",
  "files": ["character_sprite.json", "background_tiles.json", "npc_sprites.json"]
}
```

**Storage Location:** `data/users.json` (single file, JSON array)

**Constraints:**
- userName: 3-20 characters, alphanumeric + underscore
- email: Valid email format
- passwordHash: Generated by bcrypt (60 chars)
- files: Array may be empty for new users

**Relationships:**
- 1:N with ResetFile (one user owns many files)

---

### ResetFile Entity

**Purpose:** Represents a pixel art document with canvas data and edit history.

**Fields:**
- `fileName` (string, required): Name of the artwork (unique per user)
- `width` (number, required): Canvas width in pixels (1-256)
- `height` (number, required): Canvas height in pixels (1-256)
- `pixels` (Pixel[][], required): 2D array of pixel colors [row][column]
- `palette` (PaletteColor[], required): Array of predefined colors
- `history` (Model[], optional): Undo/redo stack (not stored persistently in JSON)
- `owner` (string, implicit): User name (implied by directory path)

**Example:**
```json
{
  "width": 32,
  "height": 32,
  "pixels": [
    [
      {"red": 255, "green": 0, "blue": 0, "alpha": 255},
      {"red": 0, "green": 0, "blue": 0, "alpha": 0},
      ...
    ],
    [...]
  ],
  "palette": [
    {"red": 255, "green": 0, "blue": 0, "alpha": 255},
    {"red": 0, "green": 255, "blue": 0, "alpha": 255},
    {"red": 0, "green": 0, "blue": 255, "alpha": 255}
  ]
}
```

**Storage Location:** `data/{userName}/{fileName}.json`

Example: `data/artist_jane/character_sprite.json`

**Constraints:**
- fileName: 1-50 characters, alphanumeric, no special chars
- width/height: Integer between 1 and 256
- pixels: width × height 2D array (max 256×256 = 65,536 pixels)
- palette: 0-256 colors
- owner: Must exist in users.json

**Relationships:**
- N:1 with User (many files per user)
- 1:N with Pixel (one file has width × height pixels)
- 1:N with PaletteColor (one file has 0+ colors)

---

### Pixel Entity

**Purpose:** Individual color data for a single pixel on the canvas.

**Fields:**
- `red` (number, required): Red channel (0-255)
- `green` (number, required): Green channel (0-255)
- `blue` (number, required): Blue channel (0-255)
- `alpha` (number, required): Alpha/transparency (0-255, where 0=transparent, 255=opaque)

**Example:**
```json
{"red": 128, "green": 64, "blue": 192, "alpha": 255}
```

**Constraints:**
- All channels: Integer 0-255
- Stored as object in 2D array

**Relationships:**
- N:1 with ResetFile (many pixels per file)
- Implicitly indexed by [row][column] position in pixels array

---

### PaletteColor Entity

**Purpose:** Predefined color in the pixel art palette for quick reference and recoloring.

**Fields:**
- `red` (number, required): Red channel (0-255)
- `green` (number, required): Green channel (0-255)
- `blue` (number, required): Blue channel (0-255)
- `alpha` (number, required): Alpha/transparency (0-255)

**Example:**
```json
{"red": 255, "green": 128, "blue": 0, "alpha": 255}
```

**Constraints:**
- All channels: Integer 0-255
- Usually 1-256 colors per palette

**Relationships:**
- N:1 with ResetFile (many palette colors per file)
- Index in palette array is the color index used by pixels

## Data Type Specifications

### Color Format

RGBA format: `{red: 0-255, green: 0-255, blue: 0-255, alpha: 0-255}`

- **Alpha Channel Interpretation:**
  - 0: Fully transparent (invisible)
  - 128: 50% opacity
  - 255: Fully opaque (visible)

### Coordinate System

- **Origin:** Top-left (0, 0)
- **X-axis:** Increases left to right (column)
- **Y-axis:** Increases top to bottom (row)

### Canvas Dimensions

- **Minimum:** 1×1 pixels
- **Maximum:** 256×256 pixels
- **Common sizes:** 16×16, 32×32, 64×64, 128×128

## Query Patterns

### Find User by Username
```
JSON: Array.find(u => u.userName === 'artist_jane')
MongoDB: db.users.findOne({userName: 'artist_jane'})
```

### List All Files for a User
```
JSON: fs.readdir(`data/artist_jane/`)
MongoDB: db.resetfiles.find({owner: 'artist_jane'})
```

### Get Specific File
```
JSON: fs.readFile(`data/artist_jane/character_sprite.json`)
MongoDB: db.resetfiles.findOne({owner: 'artist_jane', fileName: 'character_sprite'})
```

### Count Pixels in a File
```
Result: width × height
Example: 32 × 32 = 1,024 pixels
```

## Performance Considerations

### JSON Storage
- **File size:** Small files (1-2 MB) for typical 256×256 images with RGBA
- **Read latency:** Disk I/O, typically 1-10ms
- **Write latency:** Disk I/O, typically 5-50ms
- **Scalability:** Fine for < 1,000 users, problematic beyond

### MongoDB Storage
- **Read latency:** Network + DB query, typically 5-20ms
- **Write latency:** Network + DB write, typically 10-50ms
- **Scalability:** Supports millions of users
- **Indexes:** Compound index on (owner, fileName) for fast lookups

## Migration Considerations

### From JSON to MongoDB

1. **Create MongoDB collections** with appropriate indexes
2. **Load all users.json** records into `db.users`
3. **Load all ResetFiles** from filesystem into `db.resetfiles`
4. **Update application config** to set `USE_MONGODB=true`
5. **Keep JSON files as backup** during transition period

### Data Integrity Checks

- Verify all users in resetfiles exist in users collection
- Verify all palette colors have valid RGBA values
- Verify canvas dimensions match pixel array size
- Verify no orphaned files without owner
